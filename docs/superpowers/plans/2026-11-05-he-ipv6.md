# Optional HE IPv6 Ingress and Internet Egress Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add default-off HE tunnel termination, Proxmox incoming TCP DNAT and effective internet_egress_ports-controlled outgoing TCP/UDP/ICMP SNAT through one shared public IPv6, preserving incoming client addresses and existing IPv4/local DNS behavior.

**Architecture:** Host-config owns the SIT tunnel, dummy-interface public VIP, forwarding/routes and independent host INPUT guard. Home derives per-slot ULA /64 networks for the union of incoming-forwarding targets and guests with effective global/per-guest/role internet egress, and manages scoped nftables DNAT/SNAT/forwarding/conntrack cleanup. Both roots consume one shared he_ipv6 switch; incoming traffic preserves client identity, and permitted outgoing flows use the shared VIP as source.

**Tech Stack:** Terraform, bpg/proxmox 0.118.1, neuspaces/system 0.5.0 in both roots, existing pve-firewall backend, Linux iproute2/sysctl/systemd/nftables/conntrack-tools, POSIX shell, Terraform mock-provider tests, Node.js >=22 subprocess tests, Docusaurus.

**Spec:** [Optional HE IPv6 ingress and internet egress](../specs/2026-11-05-he-ipv6-design.md).

## Global Constraints

- Terraform >= 1.10 and < 2.0 in home; >= 1.9 and < 2.0 in reusable modules and host-config.
- Keep bpg/proxmox 0.118.1, neuspaces/system 0.5.0, lukaspustina/pihole 0.3.1 and magodo/restful 0.25.2.
- HE IPv6 defaults off; use the same shared var-file for both Terraform roots.
- One public /128 on Proxmox; isolated ULA /64 per ingress or effective-egress guest, derived from its slot; gateway offset 1, guest offset 2.
- Incoming TCP uses destination NAT and preserves client IPv6 sources; permitted outgoing TCP/UDP/ICMP uses explicit SNAT to the shared VIP.
- Reuse effective global/per-guest/role internet_egress_ports for IPv6; keep protected networks blocked and IPv4 behavior unchanged.
- Keep local DNS IPv4-only; do not edit modules/dns_records or publish public DNS.
- No live apply, automatic guest/network restart, router change or old-tunnel access.
- Preserve all pre-existing checkout changes and private tfvars; stage only this feature's own changes.
- Keep the established pve-firewall backend and existing IPv4 resource identities; never flush global rules or conntrack.

## File Structure and Fixed Interfaces

- Both roots: `he_ipv6 = object({ enabled = optional(bool, false), server_ipv4 = optional(string), local_ipv4 = optional(string), client_ipv6 = optional(string), server_ipv6 = optional(string), routed_prefix = optional(string), ula_prefix = optional(string), mtu = optional(number, 1480), protected_cidrs = optional(list(string), []), port_forwards = optional(map(object({ guest = string, port = number })), {}) })`, default `{}`, non-nullable. There is no `ingress_guest` field.
- `modules/proxmox_host.he_ipv6`: nullable settings object using the root's validated tunnel/prefix/MTU fields, default null; host-config projects enabled settings to it and ignores guest map resolution. Host outputs/status use the spec's exact property names.
- `platform_network.networks`: add `ipv6_cidr = optional(string)` to existing `{ slot, vnet_id }` entries. `guest_network.ipv6_cidr` defaults null. Its `ipv6` output is null or `{ cidr, gateway, address }`; platform, service_vm and vm carry the same nullable `network.ipv6` object.
- service_vm/vm: `ipv6_forwarded_ports = list(number)` and `protected_ipv6_cidrs = list(string)`, both default `[]`. Mapped ports are TCP only and must be a subset of declared TCP public_ports. Reuse existing effective `internet_egress_ports = list(object({ protocol = string, port = optional(number) }))` for IPv6 TCP/UDP and portless ICMPv6 too; no new egress input/flag. Existing IPv4 behavior and IPv4-only connections/allow_rules/DNS/NTP/guest role dependencies remain unchanged.
- New `modules/ipv6_ingress`: input `public_address = string`, `ula_prefix = string`, `protected_cidrs = list(string)` (default `[]`), `forwards = map(object({ guest = string, port = number, address = string, vnet_id = string }))`, and `egress = map(object({ address = string, vnet_id = string, ports = list(object({ protocol = string, port = optional(number) })) }))`. Tunnel interface fixed `hsp-he6`, zone fixed 0. Instantiate when HE is enabled and EITHER map is nonempty, including egress-only configurations. It requires the system provider and returns `generation`. Derive egress map from the SAME effective global/per-guest/role list used by service_vm; omit empty entries.
- New home outputs: `ipv6_ingress` null or `{ public_address, routed_prefix, ula_prefix }`; `ipv6_networks` map of all ingress/egress participants to `{ vnet_id, cidr, gateway, address }`; `ipv6_port_forwards` map keyed like configuration to `{ public_address, protocol, port, guest, target_address, vnet_id }`; `ipv6_egress` map of egress-enabled guests to `{ public_address, source_address, vnet_id, ports }`, with the effective configured-protocol list and null ICMP port; `ipv6_host_requirements` list of `{ purpose, direction, iface, source, destination, protocol, icmp_type }`, nullable selectors. Maps/lists empty off; port-forward protocol is `tcp`.
- Host-config `he_ipv6_status`: null or `{ interface, vip_interface, public_address, local_ipv4, remote_ipv4, local_ipv6, remote_ipv6, ula_prefix, mtu, route_metric }`. Outputs describe desired state, not tunnel health or applied external filtering.
